# AI を使ったプラグイン制作の約束

プラグインは、ほかの人のサーバーで、ほかの人のプレイヤーのために動く。作者と、そのプラグインを入れるサーバーの運営者と、プレイヤーを守るための約束。

## コードの出どころ

- 他人のプラグインのコードを、ライセンスを確かめずにコピーしたり、言い換えて持ち込んだりしない。参考にしてよいのは、公開されている API の資料と、このプロジェクト自身のコード。オープンソースのコードを使うときは、ライセンス（GPL、MIT など）と、作者のプラグインのライセンスが両立するかを作者に伝える。
- ライブラリを jar に同梱するときは、そのライセンスが再配布を認めているかを確かめる（`scripts/build-release.ps1` が同梱物を一覧にする）。
- 有名なプラグインの「そっくりさん」を、名前や見た目まで似せて作らない。

## 利用者を守る

- **頼まれていない処理を入れない**: 外部への通信（アップデートの確認、統計、ログの送信）、データの収集、OP や権限の付与、ほかのプラグインのダウンロード、ファイルの削除、コンソールコマンドの実行。頼まれたときも、何が起きるかを説明し、設定で切れるようにし、既定は控えめにする。
- 裏口（特定のプレイヤー名や UUID にだけ効く処理、隠しコマンド）を作らない。作者に頼まれても作らない。
- プレイヤーの個人情報（IP アドレスなど）を必要以上に保存・表示しない。
- 権限のチェックを省かない。管理者向けのコマンドの既定は `op` にする。
- 設定ファイルやデータを、利用者の変更を消すような形で上書きしない。形式を変えるときは移行処理を書く。

## 配布

- Hangar（https://hangar.papermc.io/ ）、Modrinth（https://modrinth.com/ ）、SpigotMC などには、それぞれ公開の規則がある（難読化の禁止、外部通信の明示、説明文の要件など）。公開を手伝う前に、その時点の規則を読む。
- 公開、タグの push、リリースの作成は、作者がはっきり頼んだときだけ行う。
- 公開用のトークンは、作者にチャットへ貼らせない。環境変数か GitHub の Secrets に入れてもらう。
- 説明文や更新履歴に、確かめていないこと（「すべての版で動く」「軽い」）を書かない。

## AI が書いたものを公開するとき

- 作者が中身を読み、テストサーバーで動きを確かめてから公開するものとして書く。
- 動かしていない機能を「できました」と言わない。確かめられなかったことは、そのまま作者に伝える（例: 「プレイヤーが必要な操作は、まだ確かめていません」）。
